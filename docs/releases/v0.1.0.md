# NodeFlow v0.1.0 — Hybrid Edge/Cloud inference orchestrator

First public build of the MVP: a native desktop app (Tauri v2 + Rust) that turns scattered ideas
into a knowledge graph and decides **per task** which engine runs the inference — a model on your
own machine, a free-tier cloud model, or a paid API — with the cost of every call accounted for.

## What works

- **Knowledge canvas** — React Flow graph with typed edges, auto-organisation, category lenses and zones.
- **One global engine selector** — pick the engine once and every AI function uses it: your machine,
  free-tier cloud, or a paid API. Any OpenAI-compatible endpoint can be added from the UI.
- **Cost accounting and caching** — tokens and USD cost per generated artifact; a hash cache keyed by
  engine so repeating a run costs nothing.
- **Local drafts with code-side validation** — a small local model proposes titles/categories/tags and a
  Rust validator accepts or rejects each field against the vocabulary that is actually in the graph.
- **Learning loop** — the app learns from what you accept, reject and delete, and can correct your
  profile by itself every *N* decisions (switch, not a button).
- **Human in the loop** — the agent proposes; nothing enters the graph without approval.
- **Obsidian vault integration** — notes are Markdown + YAML frontmatter; graph and vault are the same
  knowledge seen two ways.

## Engineering notes (with the measurements that forced them)

- **The model proposes, the code validates** — a JSON grammar guarantees shape, not truth: the local
  model returned `madurez: 100` in perfectly valid JSON. Every structured field is checked.
- **A cache key must not carry the clock** — the first implementation hashed a prompt containing
  `now_iso()` and scored 6 misses / 0 hits on identical runs.
- **No small-LLM router on the hot path** — measured 1/5 accuracy; routing is deterministic code.
- Details in [`docs/adr/`](https://github.com/NeonEden/NodeFlow/tree/main/docs/adr).

## Honest limits

- Windows only for now; no code signing, no auto-updater.
- "Local" means *no quota*: depending on your Ollama setup the daemon may serve a free cloud model.
  Truly on-device engines are the ones without `:cloud` (e.g. `granite3.3:2b`, `qwen2.5vl:7b`).
- Some models in a local daemon advertise as free but require credits (HTTP 402). The app detects
  this, marks the engine and skips it instead of failing silently.
